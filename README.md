# Отчёт по авансам подрядчикам

CLI на Python 3.10+ без внешних зависимостей. Строит отчёт на конец выбранного дня по договорам, работам и фактически перечисленным средствам. Деньги внутри программы — целые копейки, в файлах — рубли с двумя знаками после точки.

## Быстрый запуск

После клонирования приватного репозитория перейдите в его папку:

```bash
python3 --version
python3 -m unittest discover -s tests -v
python3 report.py --date 2026-11-10 --data-dir data --output-dir reports/2026-11-10
```

Windows: используйте `py -3` вместо `python3`. Устанавливать пакеты, настраивать БД или Docker не требуется.

Аргументы:

- `--date` — обязательная дата в формате `YYYY-MM-DD`, включительно.
- `--data-dir` — папка с тремя CSV; по умолчанию `data` рядом со скриптом.
- `--output-dir` — папка результата; по умолчанию `reports` относительно текущей папки. Создаётся автоматически. Файлы отчёта с теми же именами перезаписываются; для разных дат используйте разные папки.

Код завершения: `0` — отчёт построен, `2` — ошибка аргументов, входных данных или записи. Предупреждения о расхождениях идут в stderr, ошибки содержат имя файла и строку либо ID записи. Перед записью проверяется весь набор данных, включая будущие записи.

## Результат

- `works.csv` — каждая работа, включая отменённые и плановые.
- `contracts.csv` — итоги каждого подписанного на дату договора.
- `report.json` — те же таблицы, дата, правило распределения и предупреждения. Денежные значения — строки, чтобы потребитель не потерял точность.

CSV: разделитель запятая, UTF-8 с BOM для открытия в табличных редакторах. Если редактор не распознал числа, импортируйте с десятичным разделителем «точка». Готовый пример — `examples/2026-11-10/`.

### Колонки работ

| Колонка | Значение |
|---|---|
| `as_of` | Дата расчёта |
| `contract_id`, `work_id`, `title` | Договор, работа, название |
| `status` | Состояние на дату: planned / done / cancelled |
| `price` | Исходная цена работы |
| `effective_price` | Цена для расчёта: ноль после отмены |
| `direct_paid` | Фактические платежи с явной привязкой к работе |
| `allocated_advance` | Расчётная часть общего аванса |
| `paid` | Сумма двух предыдущих колонок |
| `remaining` | max(effective_price − paid, 0) |
| `overpaid` | max(paid − effective_price, 0) |

### Колонки договоров

| Колонка | Значение |
|---|---|
| `as_of`, `contract_id`, `contractor` | Дата, договор, подрядчик |
| `amount` | Исходная сумма договора |
| `active_price` | Сумма действующих работ |
| `paid` | Реально ушедшие деньги за вычетом возвратов на дату |
| `allocated` | Сумма paid по работам |
| `unallocated` | Аванс, не вместившийся в цены работ |
| `remaining` | Сумма remaining по работам, включая будущие работы |
| `overpaid` | Сумма переплат по отдельным работам |
| `contract_balance` | amount − paid; может быть отрицательным |

`remaining` — остаток финансирования всех действующих работ; срок наступления обязательства оплатить из этих данных определить нельзя. `paid` по работе включает условно распределённый аванс: это не доказательство назначения платежа. Распределение заново рассчитывается на каждую дату и может меняться при отмене или принятии работ.

## Подход и тестирование

Сначала написаны тесты требований и запущены без реализации (ожидаемая ошибка импорта `report`); они находятся в первом коммите. Затем реализованы загрузка и проверка CSV, расчёт снимка на дату, распределение и CLI. История коммитов сохраняет этот порядок. Использован стандартный `unittest`, тесты не требуют сети.

Проверяются эталонные суммы и распределение, прямой платёж, даты возврата/отмены/принятия, очередь и будущие платежи, неподписанные договоры, переплата, платёж на отменённую работу, независимость от порядка строк, сохранение денег, копейки, ошибки входа и настоящий запуск CLI. В конфигурации GitHub Actions настроена матрица для Python 3.10, 3.12 и 3.14.

Реализация разделена функциями: `load_data` проверяет вход, `build_report` рассчитывает без ввода-вывода, `write_report` сохраняет результат, `main` обрабатывает CLI. Для объёма тестового задания достаточно одного модуля.

## Допущения и ограничения

Подробные варианты, причины выбора и влияние ошибок — в [DECISIONS.md](DECISIONS.md). Записка бухгалтеру — [ACCOUNTANT_NOTE.md](ACCOUNTANT_NOTE.md). Формат входа — [data/FORMAT.md](data/FORMAT.md); исходное задание сохранено в [docs/ASSIGNMENT.md](docs/ASSIGNMENT.md).

Истории создания и изменения цен работ нет: считаем, что перечисленные работы известны с даты договора и цена не менялась. Частичные возвраты и отмена уже принятой работы форматом не представлены. Общий аванс распределяется по договорённому алгоритму, который бухгалтер ещё должна подтвердить.

**Требование Claude Code не выполнено:** эта работа сделана в Codex. Подлинного транскрипта Claude Code `/export` нет, замена или вымышленный экспорт не приложены. Это отклонение от исходного задания следует согласовать с проверяющим; если требуется именно Claude Code, работу нужно провести в нём и приложить настоящий экспорт всех сессий.

Задание, данные и решение предназначены только для приватного репозитория. Для доступа проверяющему владелец должен добавить его GitHub-аккаунт в Settings → Collaborators; приватная ссылка сама по себе доступа не даёт.

Инструкция загрузки с сохранением истории — [PUBLISH.md](PUBLISH.md). Локально проверено на Python 3.14; GitHub Actions здесь не запускался из-за отсутствия доступа к GitHub.
